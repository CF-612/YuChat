# 电脑尾巴抓取与临时短声

基线：5a86e7e；Unity 6000.4.0f1。保持 VRM、LingChat 原工程与用户配置不变。不构建 APK。

## 操作与素材

电脑端中键环绕后暂停自动注视及自动面向玩家，转到背面后右键选中尾巴提起；F 恢复视角与朝向行为。XR 不使用该查看状态。

复用现有 ling-v2 TTS 导出了开心、疑惑、惊讶、不满四组各两条临时语气词。首次冷启动生成 5.105 秒，后续单条约 0.2–0.3 秒；运行时读取本地 WAV，不在线合成互动声音。音色、语气和自然程度尚待用户试听。后续可替换资源引用而不改互动逻辑。

设置增加角色声音：拟声短声、静音、原日语 TTS。短声与静音请求在宿主跳过翻译和合成，中文、情绪和动作继续送达。抓取中断旧对话声音；持续抓住只触发一次疑惑短声；摇晃惊讶可打断低优先级短声。重复事件、过期请求及已放下的持有反应被拒绝。停止短声不终止麦克风、动作或 Held 状态。

全部角色声音复用 XrSpeechController 单一音源；资源配置保存音量、随机权重及冷却。当前 Inspector 可分别试听四组，设置页提供当前模式试听。配置资产位于 Resources/LocalInteractionVoice/Bank.asset。临时合成音频仅本地保留，Git 同步生成脚本，不将未知再分发许可的音频上传。

## 复现

```powershell
./tools/prepare-interaction-voices.ps1 -Generate -Build
```

然后运行 Unity 菜单 `YuChat/互动短声/更新本地素材配置`。已有导出文件只需运行脚本而不带 Generate。Unity 的 ShortVoiceProbe.Run 会自动更新导入配置再进入 PlayMode。

## 验证

- 宿主 26 项测试通过，包含短声路径无翻译、无 TTS 调用而保留句段与情绪。
- Unity 实际导入模型与 8 条 WAV，17 项检查通过：查看模式、真实电脑抓尾入口、声音优先级、去重、过期清理、持续抓住仅一次、静音保留 Held、F 恢复。
- 证据：evidence/short-voice-2026-11-04-r2/checks.json 与 unity.log。
- 初次检查暴露 WAV 默认未预载；已配置 PCM 预载并增加运行时 LoadAudioData，修复后回归通过。
- 这些是电脑自动化证据，不代表用户听感、Quest 手势与设备音频验收。未升级版本、未打包。
