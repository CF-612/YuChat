## 1. 当前子批与整体基础目标

**当前立即推进范围：本地 TTS + 真实 LLM 对话 + 翻译对话框 + 音频队列/停止。** 无 VRM、无角色骨架也必须能独立运行及验收。先用中文输入、中文对话正文、可查看的实际朗读文本和临时日语声线完成闭环；新模型到位后再把口型与角色表现接到相同播放事件。当前不投入旧鱼物理参数调校。

用户可以在有尺度、接触阴影和桌面关系的空间中提起小鱼；晃动时头发、裙摆等已有可动部分有惯性和收敛；松手后有可见的缓降、接触和落稳过程。角色能跟随关注目标、接受连续抚摸并发出触摸音效，同时能通过 LingChat 的对话和 TTS 能力真实回复。

以上是分批完成的整体基础目标，不能要求等待模型才能交付语音子批。文字输入 → 真实 LLM → 双语文本 → 真实 TTS → 播放，是当前最低闭环；麦克风 ASR 不作为这个闭环的前置条件。Quest 平台接线后单独验收，不用 Editor 结果冒充真机交付。

复杂情绪导演、完整作者表情编辑器、语境生成动作、自然行走和 DOT 替换继续保留在后续路线中，不进入本批前置依赖。疑问/生气/惊讶小贴纸需求保留，基础闭环完成后再接。

## 4. 实施顺序与验收

### F1：新 VRM 到位后做落地和物理质感（等待模型）

当前不执行本节模型物理调校。新模型到位先记录新 SHA、骨架、可动骨/权重、SpringBone 与碰撞数据，再应用本节。旧鱼数据仅作已有成果的事实记录，不把其参数套到新 VRM；新增模型包，旧包保留。降落姿态、碰撞尺寸和模型相关视觉验收一并等新模型。

1. 在原场景补足尺度参照、适度光照和脚下接触/离地阴影，能看出脚与桌面的距离。避免为这一步扩展成完整环境美术工程。
2. 释放采用“持有 → 受控下降 → 接触收稳 → 待机”。保存当前释放高度和合法落点，下降有连续速度与减速，接触有轻微身体收稳。第一版按用户要求做柔和降落；膝/躯干动作可采用小幅程序姿态或已核实片段，来源和骨骼占用明确。
3. 角色世界根只允许一个执行者负责。下降中再次抓起立即移交，不被旧降落回调拉回；台词/触摸不能改写根位置。不能在逻辑上早已 Idle、脚底早已落地时，仅把画面滞后在空中。
4. Editor 鼠标释放投桌面仅是输入规则，不放宽未来 MR 的接触/有效空间要求。无效落点返回安全位置的反馈要清晰；空间失效时取消轨迹并进入既有重确认流程，不能在旧空间继续下降。
5. 现场确认每组需要可动的头发、裙摆、耳尾所对应的骨链。普通抓取运动保留惯性，重置/瞬移/换模型清理旧模拟速度；核对碰撞体在 24 cm 身高下的实际尺寸和更新次序，避免重复运行两套模拟。
6. 衣物没有可动骨/正确权重时如实列出缺项，在独立派生校准/资产中修复；不覆盖旧 VRM，也不把 SpringBone 的存在当完整布料模拟通过。

交付可观看录屏：近桌面及较高处松手、慢移/摇晃/急停、下降中再抓、桌边/越界、重置。检查脚底不穿桌、落地不弹跳循环、发梢衣摆可见滞后并逐渐停止。30/60/90 帧时间步下检查下降与模拟稳定性；实际手感由用户确认。

### F2：本地 TTS、真实聊天与翻译对话框（当前优先）

施工顺序：先在无模型的测试入口实际合成本地日语并播放/停止，再接中文输入与 LLM，最后串双语显示、分句播放与错误恢复。UI 和播放状态不得依赖 `FeiyuAvatar` 加载成功。角色展示和口型是订阅者，模型晚到不能导致旧台词重播。

1. 开工先核对 LingChat 后端最新交接和可用宿主，记录实际 provider、角色来源、语言/声线及调用入口。现有临时日语路径继续可用，不等待中文训练或新的语音模型。
2. 首选复用 LingChat 已有可调用宿主；若无独立入口，则在 XR 侧准备最小本地宿主/桥接，复用可抽出的源模块和响应契约。先证明所需模块能在隔离会话运行，再扩展。不能把 Tauri command 当现成 HTTP，也不能通过往用户正在使用的桌面会话发系统消息来借用对话。
3. 施工只在 XR 工程及其派生宿主内工作；若发现必须修改 LingChat 原项目，先在交付报告说明具体接口差异，交由源施工方处理。不要悄悄引入新的平行 LLM/TTS 业务实现。
4. 完成文本输入、回复显示、真实合成、音频排队、停止/错误提示，以及可供后续口型订阅的播放事件。若后端已经提供音频，Unity 直接消费，不再按同一句重新合成。协议带会话、轮次、角色、句序和取消代次；流结束、语音结束和失败含义分开。
5. 保留一个角色人声播放所有者。正式台词与短反应按 LingChat 仲裁；触摸音效是独立非语音通道，不能抢停正式发声。停止后丢弃旧回复和旧音频；不能声称本地停止必然终止远端推理。
6. PC 承担 LLM/TTS 时明确标记依赖 PC，不能称 Quest 独立推理。角色私有资料、服务配置和凭据留在既有安全配置路径，不写进场景、录屏、日志或 APK。

翻译对话框要求：

- 默认中文正文为主，可展开查看该句实际朗读文本；临时日语声线下显示对应日文。中文是对话正文，日文是朗读译文，UI 不必假定一定先日文再译回中文。
- 源 `ReplyResponse.message` 对应中文正文，`ttsText` 对应当前朗读文本，`audioFile` 对应该句音频。**`originalMessage` 在当前 generator 中赋值为用户消息，不能误当角色日文原文。** `displaySubtitle` 是角色标题副信息，也不能当翻译字幕。
- 主模型已提供有效双语时沿用；需要补翻译时复用 `Translator` 和所选目标语言规则。现有 Translator 注入 LLM client；“本地 TTS”不代表翻译/聊天也已离线。记录实际依赖，不能宣称整个链路离线。
- 每句按同一会话/轮次/句序绑定中文、朗读文本及音频。当前字幕随播放队列推进，不能因下一句生成较快而把正在说的句子替换掉；历史区可保留已完成消息。第一版做句级同步，不扩展逐字强制对齐。
- 有中文输入、发送、停止、音量、原文展开/收起、滚动历史及清晰状态（思考/翻译/合成/播放/失败）。支持中日文字体和长句换行；UI 命中不穿透成抓取或触摸。
- 翻译失败/缺少目标语言文本时保留中文，提示语音未完成并允许重试；不让日语声线盲读中文或旧语言。TTS 失败仍保留正文和已有译文。停止、重试、换角色均保留代次检查，不能重复生成一整轮来重播已有音频。
- 本轮已核对翻译源码、响应字段和桌面队列语义，未获得本轮独立翻译测试通过证据。施工需补针对真实跨端协议的回归：缺译文、翻译片段数量异常、异步乱序、重复事件、停止后晚到和空收尾；固定夹具只用于这类回归，真实翻译/语音另外验。

当前子批验收至少包含：无 VRM 时真实本地 TTS、真实连续三轮双语对话、字幕/音频句序一致、合成等待中停止、播放中停止、翻译/TTS 失败后再次成功，以及换角色隔离。记录真实使用的服务/声线和可观看听取的证据。只有接口、缓存台词或固定假响应不满足本项。边说话边摸头在后续 F3 联合验收，不阻塞本次无模型闭环。

### F3：复用自然视线、连续触摸和音效

1. 从最新 LingChat 交互交接逐项迁移上表行为；基础触摸反馈可以接现成眼睑方案，不以新的情绪系统或完整表情 UI 为条件。
2. 注视尊重当前身体/头颈姿态，抓取和降落时不与姿态争抢。旧鱼先检查标准眼骨/LookAt 是否驱动可见眼睛，独立校准；不复制摩根 iris 节点或毫米参数。
3. 连续触摸覆盖进入、保持、移动、短暂离开、重新进入、释放、取消。接触判定跟随实际模型姿态；部位命中与相应反馈一致。
4. 音效复用已有资源与节奏/音量规则，提供音量控制。换角色、关闭、暂停时收干净，恢复时不补播积压音效。
5. 触摸只在合适时机汇总到聊天；接触保持期间无需反复请求 LLM。边摸边说、持续输入和连续语音队列不被抢断。

验收用相同视角比较迁移前后，并覆盖手挡脸、袖子、无效区域、反复短触、长按移动、音量零、说话中触摸和触摸后当前表情恢复。源回归输入/预期需要落到对应 Unity 测试，最终自然度保留用户验收栏。

## 5. 统一交付与收口
