# 历史迁移中断与旧请求竞态补验

## 范围与结果

继续 R1d/R1e 的基础可靠性，不改动作和语音播放，不迁移正在运行的用户服务数据，不生成 APK。

旧历史备份之前直接写入最终文件名，写入中断后再次启动会因文件已存在而跳过校验。现在先写独立临时文件、同步，再提交备份；若发现旧实现留下的原文件前缀，保留为带唯一标识的 incomplete 备份后重建。若内容冲突，保留两份文件并明确拒绝迁移，不提交新日志。原 sessions.json 始终保留。

历史分页改用和启动恢复相同的日志扫描入口，校验文件头、记录版本、已提交换行及该会话历史连续性。在线读取遇到未完成尾行会报告失败，不擅自截断；离线启动恢复仍按已有规则先备份再恢复。

## 可复现验证

在仓库根运行：

```powershell
cargo test --offline --locked --target-dir tools/xr-host/target/c0 --manifest-path tools/xr-host/Cargo.toml
```

最终 43 项宿主测试通过，记录在本地 `evidence/storage-recovery-2026-11-04/host-tests.txt`。

新增测试涵盖：

- 残缺备份恢复，原文件与残片均保留，重复启动正常。
- 冲突备份拒绝迁移，不生成提交标记。
- 历史页拒绝错误头、版本、序号和无换行尾行，读取过程不改磁盘数据。
- 磁盘旧句读取已经等待写锁时停止会话：返回冲突，不启动新轮，不调用语音引擎，不新增历史或事件。
- 缺口恢复已等待写锁时停止或产生新事件：返回冲突，要求重新请求，不混用不同时间的快照。

竞态测试直接将 Future 推进到等待状态，再执行停止/事件写入，最后释放写锁，不依赖 sleep 或磁盘速度。测试锁入口只在测试构建中存在。

## 验收边界

真实用户服务未重启，真实历史未迁移；测试使用独立临时目录和协议夹具。此次验证的是数据保留和请求有效性，不代表真实 TTS 听感、Unity 播放恢复或 Quest 体验通过。客户端播放恢复仍归新播放方案。
