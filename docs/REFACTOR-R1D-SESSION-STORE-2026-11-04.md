# R1d 第一批：会话存储抽离与追加迁移

模型排查已按用户要求暂停。本批推进原施工指南 R1d，不依赖 Unity 模型、不打 APK。

## 起点与复用

YuChat 起点 da52ea9；本机 LingChat vrm-mvp 只读核对 SHA 0478d5dd。继续复用现有 LLM/TTS adapter、History/Sentence 数据结构、角色关联、句段重试和音频文件引用，不改 LingChat 项目。此次修改属于 XR 独立宿主的存储职责，未移植桌面数据库或另造聊天协议。

当前本地 sessions.json 为 29,267 字节，仅统计大小，未输出聊天内容。本批选择无新增依赖的版本化 JSONL 增量存储。实际用户数据没有在测试中迁移，也没有重启当前服务；下次运行更新后的宿主才会迁移。

## 已实现

- SessionStore 统一启动读取与保存，宿主 finish 不再遍历全部会话并全量序列化。
- 按会话已保存游标只复制新增 history/sentences；序列化、磁盘追加和同步刷盘在会话总锁外执行。
- 有序写入锁由实际后台写入作业持有；等待者取消不会让尚未结束的写入提前释放顺序锁或丢失已提交游标。
- 首次读取旧 sessions.json，保留原文件和 sessions.pre-journal.json 备份。迁移先写临时文件并刷盘，再提交 sessions-v1.jsonl；带版本头的已提交日志作为迁移标记，重复启动不重复导入。
- 恢复时严格检查记录版本、角色和追加位置。末尾未完成的一行先备份整份日志再截断恢复；完整损坏行拒绝启动，不静默跳过历史。
- 追加失败不推进游标，回退到追加前长度，之后可重试。保留历史顺序与音频引用，不清理音频。

## 后续与回退边界

R1d 尚未全部完成：当前启动仍重放并保留完整历史 Vec；运行态有界缓存和磁盘分页、音频容量/引用统计待后续批次。R1e 完整句段快照恢复另行提交。

旧程序只读 sessions.json，不识别新 journal。因此迁移后若产生新聊天，不可简单切回旧程序并认为数据仍齐全；需先导出合并后的历史。本批未删除旧文件，不自动进行清理或回滚。

本机正在运行的服务未被重启，用户设置、音频、模型与未提交的其他工作均保留。
