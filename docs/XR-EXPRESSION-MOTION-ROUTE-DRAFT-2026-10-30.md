# XR 情绪、表情组合、动作与贴纸：技术路线讨论稿

2026-10-30，Asia/Shanghai。状态：**延期讨论，未派工或实施**。用户后续明确要求先做空间、物理、真实对话和自然互动基础，当前顺序以 [基础施工与验收规格](XR-FOUNDATION-BATCH-2026-10-30.md) 为准。本文保留复杂表情、贴纸和动作的设计素材，不再建议下一批先建表现系统。既有施工继续负责实现；旧蓝色大肥鱼、DOT 替换计划、LingChat 角色格式兼容及全部成果保留。

## 1. 建议的核心变化

让上帝 Agent 成为理解语境的表现导演：依据角色性格、当前说话内容、交互和可用素材，组合一份短小的表现计划。内在情绪、外在表情、身体动作、漫画式贴纸分别表示，协同执行。

旧 20 类情绪保留为兼容输入，不再作为 XR 唯一分类或表情开关。新的语义可以表达害羞、心动、羞愧、压抑、故作镇定等混合状态和意图；愉快程度、激动程度、自信/掌控程度可作为连续基础，但仅靠三个数字也不能区分所有语境。

例如“害羞但努力装作镇定”，内在情绪可以强，外显笑容可以弱、脸红逐渐增强；不必把它压成一个标签再整脸切换。强度、保持和消退由本地时间状态处理，避免每句重置、每帧请求 Agent。

## 3. 表情素材如何组织

保留三种素材身份，不强行把作者完整脸拆成小块：

- **完整表情 / 配方**：保留用户做好的整体设计，作为基础表演。一个配方可以适合多个语境，同一语境也可有多个配方。
- **局部组件**：已确认可独立控制的眉、眼、嘴等，可在明确通道范围内组合；同一部位的互斥内容由合成器仲裁。
- **独立效果**：脸红、阴影、泪光等，拥有独立强度和生命周期。效果可以来自形态键、材质透明度/颜色、贴图或作者曲线，不能假设都是同一种 morph。

每个条目需要稳定 ID、简短视觉描述、适用语境、反例/互斥条件、强度范围、占用通道和模型绑定。例如脸红可以标记“害羞、亲密、窘迫”，但不固定绑定唯一情绪；阴影注明“搭配垂眉时偏低落，搭配锐利眼神时偏威慑”，并由基础脸和语境决定最终含义。

已有目录和标签先导入，缺失描述可辅助整理为待确认建议；用户可批量修正、启用/停用、标记常用/偶尔/仅明确触发。没有可靠语义的特殊脸保留手动预览，正常通用表现仍可运行。不要求每个角色逐一手工配置才能使用，也不从陌生形态键名称直接推断完整含义。

以下组合只是讨论示意，具体用用户已有素材校对：

| 语境 | 基础脸 / 局部表现 | 可共享的效果 | 其他表现 |
| --- | --- | --- | --- |
| 害羞 | 克制笑容、短暂避开视线 | 脸红逐渐出现 | 小幅低头；贴纸可省略 |
| 心动 | 柔和眼神、目光停留 | 同一脸红效果 | 轻微靠近意图；心形偶尔强调 |
| 羞愧 | 不安眉形、收住笑容 | 同一脸红效果 | 低头、回避；不强制爱心 |
| 难受 | 低垂眉眼、嘴角下降 | 面部阴影 | 身体收敛，慢消退 |
| 阴险 / 威胁 | 锐利眼神、压眉或有意微笑 | 同一阴影效果 | 注视目标；身体姿态依角色风格 |

这些例子说明效果是可复用的视觉材料；具体情绪含义来自组合、时机与语境。

## 4. 上帝 Agent 的责任

建议由一次导演决策协调各表现通道，避免脸、身体、贴纸各自请求一个模型后相互矛盾。输入包括当前角色与台词、前文的必要摘要、交互事件、当前已执行的表现、可用素材摘要，以及被抓取/持物/说话等约束。

给 Agent 的是“脸红”“压抑微笑”等可理解且确实可用的素材描述与 ID。输出描述：当前情绪/意图、基础配方、可选局部效果及强弱、动作意图或素材、贴纸 cue、开始时机与大致持续。内部可记录简短选择依据用于排错，不向聊天界面输出调试文案。

示意：被认真夸奖后，角色想掩饰开心 → 选择“克制笑容”，加入中等脸红，略微移开视线，身体只做小动作，这句话不放贴纸。这里不要求 Agent 认识 `BlendShape42` 或计算每帧骨骼角度。

本地执行器负责校验可用 ID、范围、互斥与通道所有权，并把语义配方映射到实际角色键。完整脸一般一个主目标，过渡期间可有旧/新两份；局部与独立效果只在已确认相容的通道组合。多张完整脸不能直接把所有形态权重相加；嘴型、眨眼和视线须各自有确定的最终写入权。

随机性只在满足语境/角色/占用约束的候选中增加变化，并考虑近期使用记录。既允许重复合适表情，也允许没有动作/贴纸，避免为了轮遍素材而用错场合。每次决策保留 seed 和候选/舍弃原因，方便复现“为什么选了这张脸”。

表现计划按台词片段和实际播放事件执行，不以网络返回时刻直接换脸。导演或动作生成可与语音准备并行；超时继续已有本地表现，过期结果丢弃。尚未确定音频时长时先用语义段落，不伪造精确音节同步。已有触摸等即时本地反馈无需等 Agent。

技术实现上复用 LingChat Agent 的任务/工具协议与逻辑；其 Rust/Tauri 宿主不是可直接在 Unity 调用的现成 HTTP 服务。第一批用本地固定计划验证 Unity，再单独确定独立 XR 后端桥接或模块提取方式，不直接依赖正在使用的 LingChat 窗口、数据库或角色设置。

## 5. 角色动作与空间移动

建议三类动作来源共用一次调度：

1. **预制动作**：保留已经好看的招手、点头、姿势、走/转/停等，用于即时可靠的表现。
2. **本地程序变化**：呼吸、目光、小幅姿态、节奏与候选变化，承担连续性；不把每帧骨骼交给 Agent。
3. **真实生成动作**：按语境生成新身体片段，作为可选能力；请求中保留文本、风格约束、模型/生成器版本和随机种子，结果记录是新生成还是缓存。

my-neuro 的具体生成发布物与限制见 [一手来源核查](research-my-neuro-motion-2026-10-30.md)。计划先作为 PC 可选动作服务进行隔离试验，不能由已有 Web/Three.js 插件推断 Unity/Quest 可直接运行；Quest 本机推理和性能要另证。

本轮复核的 my-neuro 提交为 `23e5f996091f89f34d9d5d8b2c2e8752a98f626d`，body-actions 插件为 1.2.0。公开推理代码以 text + seed 生成 20 fps、22 个身体关节的位置序列，整段返回；没有独立脸部/手指和当前姿态续接输入。插件按动作文本缓存 16 项，服务忙时返回 409、没有已核到的推理取消端点。完整 DLC2 本轮仅刷新发布元数据，包内检查沿前一天证据；没有下载权重或实际推理。来源和精确版本见上述研究，不用源码机制推断本机延迟或自然度。

**走到哪里与身体怎么表演分开。** Agent 可给“靠近玩家一点”“退回安全区”等意图，本地空间控制器根据桌面边界、目标和状态选择可达落点。生成片段中的髋部平移不能同时叠加到空间根；每段动作需明确使用原地轨迹还是由唯一空间控制器接管位移。

初期混合采用片段之间交接：等待/微动 → 预制或生成片段 → 当前待机，逐步评估局部分区叠加。生成片段到来先检查关节数据、单位/朝向、时长、接触与范围，并做必要重定向；不合格则保留本地行为，不强行播放。

被触摸/抓起、手追丢失、停止、换角色都要使旧移动或生成结果失效。手指、精确接触、持物、动态脚底不滑行不能由只有身体关节的模型自动保证。现有 XR 脚圈只验证了静态站姿支撑范围；它不等同走动/裙摆/生成动作的动态碰撞或安全范围。

生成器不可用时预制动作和核心互动仍能继续。缓存允许多样化并区分来源，避免同一句提示永远命中同一段导致“生成模式”没有变化；也不为追求随机而每句话强制重新推理。

## 6. 情绪小贴纸明确保留

已核实原资源 `public/pictures/animation/疑问.webp`、`生气.webp`、`生气2.webp`、`惊讶.webp` 及心动、害羞等文件，原配置还含 CSS 动作和对应音效。

XR 把贴纸作为独立表现通道：在头部附近以面向观看者的方式显示、随角色跟随、限制数量和重复频率，可设置关闭或密度。疑问可配困惑、试探或反问，惊讶不必改变持续情绪；同一次事件按 cue ID 去重。

保留原画面与动画节奏，按实际文件帧数和时长选择序列帧/图集等 Unity 表示，CSS 的出现/摇动/淡出行为由 Unity 重现。不会把立绘整体跳跃 CSS 直接当角色骨骼动作。声音保持独立选项，贴纸出现不占角色人声或强制中断 TTS。资源引用与署名沿来源记录；未在本轮转换或复制素材。

## 7. 建议施工顺序与验收

| 次序 | 范围 | 为什么先做 / 验收出口 |
| --- | --- | --- |
| E0：表现目录与固定样例 | 复用角色包，盘点已有完整脸/组件/效果；制作组合预览入口、几组固定表现计划 | 先让用户看到“害羞/心动/羞愧共享脸红”“难受/威胁共享阴影”的实际差异；不需要 LLM/TTS 才能判断观感 |
| E1：Unity 表现执行与贴纸 | 配方合成、包络、通道占用、口型/眨眼/触摸恢复、贴纸 | 保留整脸作品；连续换情绪、说话、抚摸也不抢写；换模型缺项有合理降级。技术通过和用户接受分记 |
| E2：Agent 语境选择 | 扩展导演输出、能力候选、固定语料回放，然后接实际请求 | 表情出现得合适且有变化；否定/引用不误演、未知 ID 不执行、超时不阻断语音。接真实服务与测试时单独记录范围 |
| M0：预制动作与空间行为 | 既有动作目录、风格/冷却，最小走—转—停和限定目标 | 根位移一个所有者、十次抓放后正常恢复、边界与动态接触检查；无动作片不冒称自然行走 |
| M1：生成动作试验 | my-neuro 可选服务、重定向、缓存/新生成标记、片段交接 | 用少量同语境不同 seed 的片段比较自然度、滑脚、取消、延迟与资源；与 TTS 并发另测 |
| Q / DOT | 将已验证表现接 Quest；DOT 到位新增模型映射 | 设备输入、材质、贴纸与帧时真机验收；保留旧鱼回退，不重写 E0–M1 框架 |

E0/E1 是建议的下一批重点，不表示 E2–M1 已获实施批准。Quest 工程准备可按需要独立推进，复杂表现先在现有 Editor 调清楚。

每批沿统筹要求重新刷新来源并列“源能力→XR 现状→缺口→采用方式→目标测试”；记录采用版本、源/目标哈希、验证结果和未采用项。当前文件是技术路线候选，不更新任何能力为“已实现”或“已验收”。

新表现旁文件需要明确的版本和字段白名单。现有导入器会过滤未知字符串，不能直接往旧 settings 增加新语义字段就声称已迁移；保持旧 manifest v1 读取能力，扩展由现有导入路径显式接入。原角色文件及未知原文继续保留，旧标签只在兼容入口翻译，新的含义不强制退回 20 类。
